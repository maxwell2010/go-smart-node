# Штрафы делегаций в отдельной новой сети

Проверенный исходный `sources/DecimalDelegation.sol` сохранён без изменения. Отдельный owned-исходник, его происхождение, перечень изменённых функций и SHA-256 находятся в `UPSTREAM.json`. Историческая сборка mainnet не подменяет контракт этим исходником.

## Что изменено

В общей coin-позиции находятся прямой стейк и резерв NFT. Ранее обычный штраф затрагивал обе части, а NFT-маршрут повторно штрафовал NFT-резерв. Для 40 DEL прямого стейка и 60 DEL резерва NFT штраф 10% давал 84 DEL либо 84,6 DEL в зависимости от порядка обработки. Теперь обычный штраф применяется только к прямой части. Обе последовательности дают 36 + 54 = 90 DEL.

Сохраняется исходное округление каждой пользовательской позиции. Сжигается сумма фактически вычисленных индивидуальных потерь. Например, две позиции по 3 минимальные единицы при штрафе 50% сохраняют требования 2 + 2. Старое глобальное сжигание 3 оставляло только 3 единицы обеспечения. Новый путь сжигает 1 + 1, выдаёт обеим сторонам по 2 и оставляет пустой escrow.

Списание происходит лениво: при явном применении штрафов к позиции либо перед её выходом, переводом или возвратом владельцу. Потеря прямого WDEL одновременно уменьшает его предложение и нативное предложение SDK bank. NFT-контракт сам сжигает свой резерв; companion-позиция и агрегатный резерв только отражают эту фактическую потерю и не сжигают её второй раз. Все изменения входят в одну транзакцию.

Глобальный `applyPenaltiesToValidator` больше не сжигает процент от агрегата. Он подтверждает текущий целевой индекс, событие `PenaltyAppliedToValidator` содержит нулевую сумму. Этот индекс не означает, что все позиции уже обработаны. `getValidatorReserve.reserve` хранит сумму активных записей с уже реализованными потерями: для ещё не обработанной позиции запись остаётся исходной. Это не оценка окончательной чистой суммы после всех ожидающих штрафов. Замороженные требования учитываются отдельной очередью, после выхода из bonded-позиции её резерв списывается из агрегата.

Перед отделением NFT сначала обрабатывается его ожидающий штраф, затем прямая часть coin-позиции, пока NFT ещё отмечен как обеспечение. Только после этого снимается pairing. Такое же правило действует для обычного выхода, перевода и административного возврата, для DRC721 и DRC1155.

У DRC1155 метод `penalty` возвращает количество NFT, а не резерв в минимальных денежных единицах. Его API сохранён. Caller вычисляет фактическую потерю как разность `getReserve` до и после вызова проверенного NFT-контракта. Изменение типа резерва или его увеличение вместо штрафа отклоняется. Округление самого NFT-контракта не переопределяется. Остаток целого пула, не вошедший в `floor(pool / supply)`, не распределяется выдуманным правилом между владельцами.

## Проверки и воспроизведение

Приватное приложение с настоящей EVM выполняет подписанные транзакции через обычные методы контрактов. Проверяются два порядка штрафа 40/60, реальные изменения предложения SDK/WDEL, две очередности выдачи требований 3/3, повторная обработка, ожидающий штраф перед выходом/переводом/возвратом NFT, DRC1155 с большим uint256 tokenId и денежными единицами, остаток NFT-пула. Отдельно развёрнутые исходные контракты сохраняют отрицательные контроли исходных ошибок.

```sh
cd network
go test -mod=readonly -p 1 -count=1 -run '^TestOwnedAppSignedRegistryBootstrap$' ./systemcontracts
SOLC=/path/to/pinned/solc python3 systemcontracts/build_owned_delegation.py
```

Solidity 0.8.20, viaIR и optimizer runs=200 закреплены вместе с SHA-256 компилятора. Сборщик проверяет исходный манифест и owned-хеш. Runtime библиотеки проверяется по compiler-derived immutable references и заранее известному адресу её создания, без одобрения наблюдённого кода самим собой. Для линковки используется `owned/DecimalDelegation.sol:DelegationNFTLib`.

ABI основного gateway сохраняется; библиотека получает явный helper для реализации coin-штрафа. Временной смысл глобального события изменён, индексаторы должны учитывать описанную выше семантику. Настройка оптимизатора не менялась ради ограничения EIP-170.

## Оставшиеся условия полного выпуска

Этот набор не включает полный native receipt controller, его подключение ко всем разрешённым входам, исторический replay, межсетевые IBC-проверки и денежную проекцию всех случаев NFT с несколькими владельцами. Сейчас контракт читает весь массив истории штрафов; нужен отдельный ограниченный count/range catchup с явным курсором до допуска финансовых маршрутов в окончательный релиз. Проверки не отправляют транзакции в публичную сеть и не изменяют работающие ноды.
