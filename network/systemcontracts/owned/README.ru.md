# Исправление повторного штрафа NFT-резерва

Этот исходник предназначен для отдельной новой сети. Проверенный исходный `sources/DecimalDelegation.sol` сохранён без изменения; происхождение и SHA-256 указаны в `UPSTREAM.json`.

В исходном контракте общая coin-позиция содержит прямой стейк и резерв NFT. Обычный штраф уменьшал всю coin-позицию, затем NFT-маршрут повторно уменьшал её NFT-часть. В подписанном тесте настоящей EVM прямой стейк 40 DEL и резерв NFT 60 DEL после штрафа 10% давали 84 DEL при порядке coin/NFT или 84,6 DEL при обратном порядке. Исправление применяет обычный штраф только к прямой части. NFT-маршрут отвечает за NFT-резерв. Обе последовательности дают 36 + 54 = 90 DEL. Несогласованное превышение NFT-резерва над общей позицией вызывает ошибку, без скрытого обнуления.

Изменены только две реализации `_applyPenaltiesToStake`: в библиотеке и основном контракте. ABI сохранён. Это самостоятельное исправление, без изменения округления пользовательских требований, глобального расчёта штрафов и способа сжигания предложения.

## Проверка

`systemcontracts/mixed_penalty_app_test.go` выполняет реальные подписанные транзакции в закрытом приложении с настоящей EVM: создание NFT, внесение резерва, делегирование, штраф и оба порядка обработки. Сравнение с отдельно развёрнутым исходным контрактом сохраняет воспроизводимый отрицательный контроль. `rounding_app_test.go` показывает отдельный незакрытый дефект: для двух позиций по 3 минимальные единицы при штрафе 50% индивидуальные требования равны 2 + 2, а глобальное сжигание 3 оставляет только 3 единицы обеспечения.

```sh
cd network
go test -mod=readonly -p 1 -count=1 -run '^TestOwnedAppSignedRegistryBootstrap$' ./systemcontracts
SOLC=/path/to/pinned/solc python3 systemcontracts/build_owned_delegation.py
```

Компилятор Solidity 0.8.20, viaIR, optimizer runs=200 закреплены сборщиком вместе с SHA-256 бинарного файла и исходников. Повторная сборка даёт побайтно одинаковые артефакты `MintCandyDelegation` и `MintCandyDelegationNFTLib`. Runtime основного контракта 24376 байт, предел EIP-170 24576 байт; запас 200 байт. Для библиотеки используется явная ссылка `owned/DecimalDelegation.sol:DelegationNFTLib`.

## Оставшиеся условия выпуска

Это исправление само по себе не закрывает финансовый выпуск. Исходный агрегатный штраф WDEL переводит токены на нулевой адрес и отклоняется новым стандартным wrapper. Исходный NFT-штраф с нативным DEL уменьшает резерв, но не предложение SDK bank. Нужны отдельный атомарный native burn, консервативное списание только реально вычисленных индивидуальных потерь, отсутствие повторного глобального сжигания, проверки DRC1155 и полной выдачи средств в обоих порядках. Глобальный `validatorReserve` до такого изменения отражает ленивое исходное состояние, его нельзя выдавать за полностью пересчитанную чистую сумму требований. Проверки этой группы не отправляют транзакции в публичную сеть.
