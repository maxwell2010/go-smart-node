# Общая координация нативных receipt-планов

Компонент пока не подключён к App. Он не заменяет проверку EVM-источника,
обеспечения, NFT-родословной или допустимой мощности валидаторов.

`New` требует три планировщика в фиксированном порядке: assets, NFT,
validator/bindings, а также итоговый проверяющий компонент. Каждый
`Preparer.Prepare` возвращает `Prepared` с `Validate` и `Apply`. Подготовка
и проверка выполняются в отдельных отбрасываемых SDK-кешах на старом нативном
состоянии. Все три `Validate` должны пройти до первого `Apply`. Далее изменения
применяются в одном общем дочернем кеше, в том же порядке, и проверяется итог.
Ошибка любого этапа исключает commit всех нативных изменений и событий.

`Apply` может проверять собственные ожидаемые строки, но не должен сравнивать
снимок другого модуля с его старым состоянием после законного изменения этим
модулем. Повторные state-changing EVM-вызовы внутри стадий запрещены контрактом
интерфейса: всё исполнение EVM должно завершиться до подготовки планов.

Планы получают независимые копии receipt и EVM message, включая logs/data,
AccessList, uint256-значения и ссылки на адреса. Отдельно ограничены число logs,
variable payload и логический вес копируемых полей каждой копии, включая
контейнеры и фиксированный envelope. `MaxCopyWeight` не ограничивает Go heap
точным числом байт: округление аллокатора и накладные расходы runtime здесь
не измеряются. Количество объектов и длины входов отдельно ограничены.
Эти пределы и фиксированные веса должны быть единой политикой сети;
их нельзя произвольно менять локальным конфигом консенсусной ноды.
Копирование переменного входа и обход
контейнеров учитываются в унаследованном SDK meter. Постоянная обработка пустого
envelope относится к intrinsic work; пустая нерелевантная транзакция не должна
получать дополнительные KV/EVM-чтения от конкретных планировщиков.
Сброса meter нет. OOG передаётся обычной внешней границе Ethereum/SDK/Gov,
при этом общий дочерний кеш не коммитится. SDK сам переносит события при
успешном commit; второй ручной перенос не применяется.

`EthereumHooks` и `GovernanceHooks` фиксируют тип маршрута в Go-адаптере.
Непроверенные NativeSDK/IBC маршруты явно отклоняются. Пустой transaction hash
не служит глобальным ключом дедупликации: два внутренних вызова одного блока
могут быть разными выполнениями. Контекст одного выполнения нельзя повторно
использовать для вложенной или отложенной обработки общего pipeline.

Если receipt содержит block height/hash, они сверяются с текущим SDK context.
Отсутствие этих полей допускается для существующих внутренних и оценочных
receipt. Это проверка согласованности, а не доказательство исполнения EVM:
проверенные адаптеры обязаны передавать receipt текущего выполнения ровно
один раз. Повтор произвольно переданного receipt этим общим API не превращается
в новое подтверждённое исполнение. Постоянный глобальный hash-ledger не вводится.

Обычные тесты на настоящем SDK store проверяют порядок стадий, предварительную
валидацию, независимость входов, discard подготовительных записей, поздний
отказ, итоговый отказ, OOG, отсутствие повторных событий и отдельные внутренние
выполнения с пустым hash. Это тесты координации с явными планами записей,
не доказательство совместной финансовой модели. До активации нужны конкретные
планировщики, аутентификация и signed App-тесты общей цепочки с реальными
EVM/Bank/NFT/Validator изменениями. Неподдержанные внутренние вызовы и callback
маршруты должны оставаться отключёнными до собственных атомарных адаптеров.
