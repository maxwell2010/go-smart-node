# Проверка NFT-контрактов и чтение владельцев

Пакет предоставляет production-реализацию интерфейсов `receipts.Authenticator`
и `receipts.FinalReader` для отдельной новой сети. Конфигурация задаёт chain ID,
EVM chain ID, адреса registry, NFTCenter, UnifiedDelegation, его библиотеки и
ограничения работы. Владелец системных контрактов должен совпадать с адресом
SDK-модуля governance.

Ожидаемый код строится из артефактов закреплённого компилятора и известных
параметров конструктора/линковки. Проверяются ERC1967-прокси и реализации трёх
системных ролей, библиотека делегаций, связь factory с registry и единый адрес
`delegation`/`delegation-nft`. Для коллекции дополнительно проверяются её native
индекс, активная запись `NFTState` в factory, стандарт и тип обеспечения,
реализация нужного семейства, beacon и точный runtime дочернего прокси.

Этот профиль принимает текущие проверенные артефакты релиза. Обновление на
неизвестную реализацию требует отдельного ревью и обновлённых артефактов ноды.
Хеш обнаруженного в сети кода не становится разрешением сам по себе.

Поддерживаются NFT721 и NFT1155 с резервом и без него. При паузе factory
используется явный `readImplementation(uint8)` и свежий прокси с разрешёнными
view-селекторами. Чтение владельцев остаётся доступным; финансовые ограничения
паузы сохраняются в контрактах. Старые mainnet-прокси относятся к отдельной
исторической сборке и этому профилю не соответствуют.

`Ownership` повторно проверяет профиль коллекции. Для NFT721 он читает
`ownerOf` полного uint256 ID; для NFT1155 - `balanceOf(owner, id)` каждого
запрошенного владельца. Результаты ограничены native-диапазоном количества.
Все вызовы используют настоящий ограниченный `core.Message.GasLimit`,
одноразовые discarded cache-контексты и точные ABI-границы ответа 32/96 байт.
Работа EVM и SDK оплачивается через унаследованный gas meter, включая
исчерпание локального бюджета чтения.

Защитные пределы конфигурации: до 256 владельцев и 10 000 единиц, EVM-бюджет
одного getter от 21 000 до 5 000 000 и SDK-бюджет операции до 20 000 000.
Параметры конкретного запуска нужно выбирать по интеграционным измерениям.
Неизвестная native-коллекция возвращается как незарегистрированная; повреждённый
индекс, устаревшая привязка, неверное семейство или нехватка бюджета дают ошибку.

Пакет только читает состояние. Допуск новых коллекций, native mint/burn,
сопоставление резервов и подключение к общему NFT/validator orchestration
остаются отдельными этапами. Тестовый native metadata provider в signed App
проверяет чтение уже допущенной коллекции и не заменяет финансовый допуск.

## Измерения текущей реализации

В signed App fixture для одного внешнего NFT key и двух владельцев отдельная
аутентификация заняла около 1,26-1,28 млн SDK gas; `Ownership`, повторяющий
аутентификацию, - 1,48-1,78 млн. Вместе это около 2,75-3,06 млн. Native metadata
в этом замере представлен fixture provider, поэтому стоимость реального чтения
native-индексов и токенов нужно прибавить отдельно.

Внутренние discarded вызовы выполняются с `internal=true`: transaction minimum
fee floor к ним не применяется. Контрольное удвоение EVM read cap со 100 000 до
200 000 оставило SDK gas аутентификации точно тем же. Ограничения VM/SDK и
оплата фактической работы сохраняются.

`Plan` и `Apply` повторяют проверки. Для одного key составляющая auth/ownership
по текущей структуре примерно удваивается до 5,5-6,2 млн, ещё до native snapshot,
stake capture и записей. Это расчёт по отдельным измерениям, а не замер готового
общего pipeline. Перед включением нужны совместные end-to-end измерения;
переиспользование проверок допустимо только с явно ограниченной областью
execution и проверкой неизменности состояния.

## Явный профиль изолированных позиций

`Config.Protocol=ProfileIsolatedPositionsV1` задаётся явно вместе с адресами
`PositionVault` и `WrappedDEL`. В этом профиле код Gateway соответствует только
`MintCandyIsolatedDelegation`, origin1155 - только `MintCandyIsolatedDRC1155`.
Дополнительно проверяются ERC1967 vault, Gov-владелец, registry roles, фабрика,
библиотека и точные compiler/runtime templates. Профиль `ProfileSharedReference`
остаётся отдельным control для чтения старой shared-модели; он не включает
финансовый допуск изолированных позиций и не принимает isolated role bindings.

`Position(ctx, fullUint256ID)` возвращает неизменяемые по ссылкам fixed-width
поля фактического состояния. Для активной позиции проверяются origin, qty1..1024,
owner, parent, backed currency kind, собственный declared reserve, совокупный
объявленный резерв этой валюты и реальные holdings vault. Необъявленный surplus
остаётся отдельным остатком и не увеличивает резерв позиции. Для WDEL проверяются
код обёртки, её totalSupply и нативное обеспечение. Другие ERC20 сейчас дают явную
ошибку отсутствующего approved backing reader; их admission требует отдельной
проверки actual coin economics и native coin adapter.

Closed snapshot принимается только при подлинном vault/runtime, ID меньше
текущего nextPositionId, статусе Closed, нулевом owner и полностью очищенной записи.
Ошибка или revert `ownerOf` не считается доказательством закрытия. Такой snapshot
не разрешает native compaction сам по себе: план должен повторно проверить
актуальное состояние и полную lineage в атомарном orchestration.

Чтение не требует новых origin view-селекторов: необходимая policy уже хранится
в vault, а код origin проверяется через NFTCenter и compiler template. Поэтому
ordinary signed controls читают active/closed позиции при паузе factory и vault,
сохраняя финансовые ограничения. Положительные проверки используют реальные
Gov-owned Gateway/registry/factory/vault и подписанные пользовательские операции;
native collection admission в этом reader-тесте остаётся metadata fixture.
Проверены полный ID больше2^200, full split с закрытым родителем, wallet transfer,
неизменённый surplus, DEL/WDEL collateral, неправильный domain и недостаток бюджета.

В этом fixture одно чтение active DEL позиции расходует около2,44 млн SDK gas,
WDEL -2,57 млн, closed proof -1,88 млн. Значения не включают проверку native lineage
и полный NFT/validator pipeline. Увеличение production budgets не выполнялось.
Пакет не включает App financial hooks, mint admission или новые IBC callbacks.
