# Нативное хранилище валидаторов в приложении

В новой development-сети модуль `validator` монтирует отдельное SDK-хранилище
и настоящий `StateKeeper`. Зарегистрированы genesis/export и запросы
`Params`, `Validator`, `HistoricalInfo`. Отсутствующая запись возвращает
NotFound; прочие ещё не подключённые запросы возвращают Unimplemented.
SDK staking не подставляется в ответы нативного модуля.

Модуль не устанавливает Msg-маршруты и BeginBlock/EndBlock обработчики.
Консенсусный контроллер, голосование с нативными/NFT-позициями, награды,
штрафы и обработка результатов контрактов ещё требуют общей активации.
Приложение допускает только явный пустой нативный validator genesis
с базовым denom `del`. Непустое финансовое состояние не принимается
до аутентифицированного bootstrap и сверки обеспечения и консенсуса.

Общая App-регрессия проверяет настоящий смонтированный keeper и gRPC-маршрут
в отбрасываемом cache, затем обычный InitChain приложения. Финансовые Msg
должны оставаться недоступны. Это не подтверждение финансовой интеграции.

Добавление store является изменением схемы новой сети. Для этого
development-формата используется новый home/genesis; перенос существующей
базы требует отдельной проверенной store migration. Decimal mainnet и
legacy replay используют другую сборку.
