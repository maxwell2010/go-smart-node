# Нативный переход состава валидаторов

`EndBlockValidatorUpdates` формирует настоящие ABCI `ValidatorUpdate` из
нативных записей Decimal. SDK staking и его финансовые shares для этого не
используются. Изменение предыдущих мощностей, статусов и исторической записи
производится в общей SDK cache-транзакции.

Приложение передаёт два разных набора:

- `effective` - фактический состав Comet для текущего блока H. Его hash обязан
  совпасть с `ValidatorsHash` заголовка. История сохраняет именно этот состав.
- `eligible` - полный список допущенных и не приостановленных участников из
  проверенного локального состояния MasterValidator. Нельзя выводить этот
  список из `BondStatus`: статус Bonded описывает выбранный состав, а допуск
  контракта может сохраняться у участника вне первых MaxValidators.

Из допущенных участников выбираются первые MaxValidators с положительной
нативной мощностью без jail. Порядок: мощность по убыванию, затем consensus
address по возрастанию. Только выбранные участники получают Bonded. Исключённый
участник может вернуться после увеличения мощности при сохранённом допуске.
Действительный consensus key берётся из неизменяемых метаданных участника.
Удаления возвращаются Comet с мощностью0. Пустой состав отклоняется.

Возвращённые из EndBlock H изменения вступают в действие в Comet на H+2.
Тест использует настоящий Comet `UpdateWithChangeSet` и проверяет различие
истории H/H+1 и H+2 при изменении мощности, jail, исключении и добавлении.
Также проверены повтор без изменений, ограничение состава, возврат исключённого
участника и откат предыдущих мощностей при поздней ошибке записи истории.

Этот компонент ещё не подключён к приложению. Требуются получение полного
допуска из контрактов, подтверждённые receipt-переходы делегаций, расчёт нативной
мощности с сохранением согласованной агрегатной политики, начальное состояние
InitChain и сохраняемая очередь фактически действующих составов для H/H+1/H+2.
Передавать текущие изменённые записи как `effective` без учёта задержки нельзя.
Возврат updates сам по себе не доказывает корректность genesis или перезапуска.

Массовая смена статусов пока использует проверенный `SetValidator` для каждой
записи, который повторно проверяет совокупность метаданных. Оценка стоимости и
атомарная пакетная оптимизация обязательны перед подключением больших наборов.
