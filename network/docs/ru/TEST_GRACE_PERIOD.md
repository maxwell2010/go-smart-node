# Грейс-период для настройки тестовой сети

Грейс-период - временный интервал без штрафов и автоматического исключения валидаторов. В этой реализации он разрешён только для изолированных тестовых EVM chain ID 990001..990099. Публичный кандидат MintCandy и сеть Decimal не допускают такой параметр.

Это общий параметр genesis `app_state.withdrawal_settlement.test_grace_until_height`, последний блок периода включительно. Значение 0 сохраняет обычные правила. После указанной высоты правила возвращаются автоматически, без локальных переключателей. На время периода отключаются финансовые штрафы за простой и двойную подпись, jail и постоянное исключение ключа по таким нарушениям. Отметки простоя за этот период не попадают в последующее окно, а доказательства нарушения в грейс-периоде не приводят к штрафу задним числом.

Подписи блоков, проверка доказательств, необходимый кворум и правила владения средствами продолжают действовать. Если подписей недостаточно для нового блока, сеть останавливается и в грейс-периоде. Комиссии за транзакции продолжают взиматься.

## Подготовка новой изолированной сети

На копии ещё не запущенного тестового genesis:

```sh
mcnd test-grace-genesis --input-file ./genesis.test.json --output-file ./genesis.grace.json --evm-chain-id 990001 --until-height 1000
```

Команда только создаёт новый файл, не перезаписывает существующий и не подключается к нодам. Остальные разделы genesis сохраняются. Высота 1000 здесь пример; это количество блоков, а не гарантия длительности в часах. До запуска все участники должны проверить одинаковый genesis и его SHA256.

Обычные флаги включения native consensus и штрафных профилей нужно оставить включёнными: они задают правила, которые возобновятся после периода. Нельзя включать грейс-период редактированием `app.toml`, переменной окружения или заменой genesis у работающей ноды. Для уже начатой сети требуется согласованное обновление состояния или новая отдельная тестовая сеть.

## Проверки

`TestOwnedAppNativeTestGraceLifecycle` проверяет подписанную EVM-делегацию во время периода, отсутствие наказания, перезапуск базы, позднее доказательство старого нарушения и возобновление штрафа с исключением ключа за новое нарушение. Тесты keeper дополнительно проверяют окно простоя, повтор, неправильную voting power и отказ при некорректном доказательстве. Результаты конкретного Linux CI следует сверять по commit, а не по наличию тестовых файлов.
