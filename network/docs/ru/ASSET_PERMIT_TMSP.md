# Разрешение по подписи для пользовательских активов tMSP

В тестовой ветке владелец обычного EVM-кошелька может подписать разрешение EIP-712. Другой кошелёк доставляет подпись вызовом `permit` и оплачивает газ. Владельцу нужно показать адрес оператора, объём выдаваемых прав, адрес контракта и срок предъявления подписи. Успешный permit сам не переводит активы.

## Какие права получает оператор

| Актив | Структура EIP-712 в точном порядке | Результат |
|---|---|---|
| DRC20 с резервом и без | `Permit(address owner,address spender,uint256 value,uint256 nonce,uint256 deadline)` | Устанавливает allowance в атомах токена. Для отзыва владелец отправляет approve(spender, 0). |
| DRC721 с резервом и без | `Permit(address spender,uint256 tokenId,uint256 nonce,uint256 deadline)` | Выдаёт разрешение на один ID. Проверка через getApproved(tokenId). Владелец может очистить разрешение через approve с нулевым адресом. |
| DRC1155 с резервом и без | `Permit(address spender,uint256 nonce,uint256 deadline)` | Даёт оператору право перемещать все ID этой коллекции у владельца. Проверка через isApprovedForAll(owner, spender). Для отзыва владелец отправляет setApprovalForAll(spender, false). |

## Данные для SDK и кошелька

1. Сверьте профиль `mintcandy_990098-1`, EVM chain ID `990098`, исходную фабрику и семейство актива. Возьмите название из `name()`. Домен содержит `name`, `version: "1"`, `chainId` и `verifyingContract` (адрес экземпляра токена или коллекции). Вычисленный хеш домена должен совпасть с `DOMAIN_SEPARATOR()` этого экземпляра.
2. Прочитайте nonce на одной высоте с доменом. Для DRC20 и DRC1155 это `nonces(owner)`, для DRC721 это `nonces(tokenId)`. У DRC721 подпись проверяется против текущего ownerOf(tokenId). Версия контрактов увеличивает этот nonce при предъявлении permit. Отзыв существующего on-chain разрешения сам по себе не аннулирует ранее выданную, ещё не предъявленную подпись.
3. Кошелёк владельца подписывает typed data с `primaryType: "Permit"`. Укажите `deadline` как Unix-время в секундах. Для DRC1155 в подписываемой структуре три поля, а в вызове контракта передаётся также адрес владельца. Ветка поддерживает подписи EOA с каноническим low-S и v равным 27 или 28.
4. Плательщик газа отправляет транзакцию с нулевым value непосредственно на экземпляр актива. DRC20 принимает `permit(owner, spender, value, deadline, v, r, s)`, DRC721 принимает `permit(spender, tokenId, deadline, v, r, s)`, DRC1155 принимает `permit(owner, spender, deadline, v, r, s)`. Nonce подписи независим от nonce транзакции плательщика.
5. После получения успешной квитанции сверяйте событие Approval (DRC20/DRC721) или ApprovalForAll (DRC1155) и значение разрешения на высоте блока. Nonce разрешения увеличивается на единицу. Истечение deadline ограничивает время предъявления подписи. Уже выданные в блоке права действуют по правилам токена до расходования, отзыва или смены владельца конкретного DRC721.

Профиль контролирует срок, владельца, домен, nonce, итоговое разрешение и событие. Отказ при неверной или повторной подписи сохраняет предыдущие права. Газ за включённую неуспешную транзакцию оплачивает отправитель.

В DRC721 счётчик подписи для ID увеличивается при использовании permit. Обычный перевод очищает выданное разрешение и сохраняет этот счётчик. Если NFT вернётся прежнему владельцу, его ранее подписанное, ещё не использованное разрешение может снова действовать до срока deadline. Кошельку следует показывать срок перед подписью.
