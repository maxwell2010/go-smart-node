# Проект публичного запуска MintCandy Network

Статус: **DRAFT / НЕ УТВЕРЖДЕНО**. Программный
[релиз mcnd 1.0.0](https://github.com/maxwell2010/go-smart-node/releases/tag/v1.0.0)
опубликован. Публичная сеть, genesis, распределение и состав операторов этим
документом не запускаются. Работающие ноды, их службы и базы не меняются.

Главный лист решений: [что утвердить основателю](LAUNCH_APPROVAL.md).
Числа ниже - одно базовое предложение вместо прежних несогласованных примеров.
Четыре оператора рекомендованы; утверждённое число `N` пока `null`.
Пять валидаторов из прежней переписки были примером.

## Предлагаемое распределение 5 041 400 MSP

Основатель выбрал свой кошелёк без дополнительных подписей для первого
распределения и запросил 5 000 000 свободных MSP. Отдельной казны 9 600 MSP
в новом расчёте нет. Общий выпуск ниже получен добавлением прежних
предлагаемых стейков/gas/резервов к свободным пяти миллионам. Это проект
начального выпуска, не утверждение новой инфляции или максимального cap.

| Назначение | MSP | Учёт / владелец |
| --- | ---: | --- |
| Свободный баланс основателя | 5 000 000 | `0x40900a48273644768c09183e00e43528c17a29f6`, контроль адреса подтвердить |
| Стартовые MSP-делегации | 40 000 | Четыре по 10 000, предложенный владелец - основатель; обеспечение на WDEL |
| Gas операторов | 800 | Четыре расходных адреса по 200; отдельно от стейков |
| Gas IBC-relayer | 200 | Два расходных адреса по 100; роли и владельцы ещё не выбраны |
| Обеспечение начального DRC20 | 300 | На контракте утверждённой монеты; параметры и владелец не выбраны |
| Обеспечение начального ERC1155 | 100 | Предложены 100 единиц по 1 MSP; collection/ID/владелец не выбраны |
| **Итого** | **5 041 400** | **`5041400000000000000000000 del`** |

[Машиночитаемый план](public-launch-allocation.draft.json),
[подробно о владении и учёте](FOUNDER_BOOTSTRAP_DRAFT.md).
После такого распределения у основателя были бы 5 000 000 свободных MSP и права
на 40 000 MSP в стейках. **Это проект, а не существующий баланс.** Обеспечение
WDEL учитывается в bank supply один раз; его нельзя одновременно начислить
как свободные MSP владельцу. Резервы DRC20 и NFT тоже входят в те же 5 041 400 MSP.

Founder-owned делегации оставляют весь начальный стейковый капитал под
контролем одного владельца. Независимые consensus keys операторов не устраняют
эту концентрацию капитала и прав делегатора/управления. Передача стейков
операторам - отдельная альтернатива; не считать её согласованной автоматически.
Награды из комиссий без эмиссии и автоматические порционные выплаты уже выбраны.
Распределение не устанавливает цену, ликвидность или право на DEL Decimal.

## Важное условие полного профиля v1.0.0

Просто оставить пустыми начальные NFT/DRC20 в полном профиле нельзя:

- Включённый NFT-профиль требует обеспеченный origin, связанные native metadata,
  origin/receipt collections и один пустой PositionVault с первым ID 1.
- TokenCenter/CurveConverter требуют от одной до четырёх утверждённых обеспеченных
  DRC20. Начальный вариант предлагает одну монету с резервом 300 MSP.
- Поэтому создание обоих активов, их имена, владельцы, supply/минимальный supply,
  минимум резерва, параметры кривой и операции owner требуют явного согласования.
  NFT в этом предложении исходно не делегирован: его 100 MSP находятся на origin.

Основание: [withdrawal_genesis.go](../../app/withdrawal_genesis.go),
[custom_collateral_registry.go](../../app/custom_collateral_registry.go).
Это требования принятия genesis, а не предложение дополнительно выпустить MSP.
MSP-only запуск без этих активов потребует отдельного набора флагов и ролей,
а также собственной изолированной проверки InitChain. Он не является готовой
заменой полному профилю. Действующий код в рамках подготовки не меняется.

## Предлагаемый состав и параметры

Рекомендация: четыре независимых равновесных оператора, по 25% мощности.
Для блока нужны строго больше 2/3 мощности: три из четырёх дают 75%.
Один отказ допустим, два должны остановить выпуск блоков. Для пяти равных
операторов нужны четыре подписи, а не три. Автоматически снижать порог нельзя.

| Параметр | Предложение / уже принятое правило |
| --- | --- |
| Стартовый состав | 4 оператора, подтвердить N, имена и владельцев стейков |
| Максимум активных валидаторов | 16, утвердить отдельно от стартового N |
| Комиссия оператора | 5% от его доли наград, подтвердить каждым оператором |
| Gas блока | 24 000 000, без увеличения для обхода ограничений |
| Вывод обычного MSP | 28 дней; таймер Gateway должен совпадать |
| Давность доказательств | 100 000 блоков и 48 часов; оба условия учесть при выплате |
| Простой | Окно 1000 блоков, минимум 50% подписей, штраф 1%, jail 1 час |
| Двойная подпись | Уже выбрано: 5% от подверженного штрафу стейка на момент нарушения; поздние депозиты защищены |
| Возврат после двойной подписи | Уже выбрано: старый consensus key исключается навсегда; новая регистрация с новым ключом |
| Делегации и награды | До 1000 native records на валидатора; выплаты порциями до 64 получателей |

Холодный финансовый genesis ограничен 16 исходными позициями; предложенные
четыре помещаются в лимит. Прямых governance-голосующих - до 256 на предложение.
Пять серверов одного владельца не равны пяти независимым операторам.
Величины gas-price/fee market, governance quorum/депозиты/сроки нужно получить
из полного defaults v1.0.0 и согласовать до финальной репетиции; null не заменять
выдуманными значениями. Текущие дефолты не становятся утверждёнными сами по себе.

## От утверждений до запуска

1. Утвердить [лист решений](LAUNCH_APPROVAL.md), реальные N, распределение,
   владельцев активов/стейков. Получить заявки и проверить контроль ключей.
2. В GitHub CI на изолированной копии создать полные defaults точной v1.0.0,
   развернуть утверждённые системные контракты, сформировать authenticated storage,
   native metadata и bindings. Не переносить тестовые ключи и состояния в public genesis.
3. Сверить сумму bank balances с supply/base_volume, MSP/WDEL, резервы origin/DRC20.
   Fee collector и native reward escrow на genesis должны иметь ноль MSP.
   Выполнить CLI genesis validate, настоящий InitChain и проверку набора/мощностей.
4. На эквивалентном тестовом genesis с одноразовыми CI keys проверить выбранный
   состав, потерю одного узла, догоняющий peer, restart, AppHash, complete/штрафы/IBC.
   Тестовыми ключами не подписывать будущую публичную цепь.
5. Собрать публичные P2P/RPC/REST/gRPC и владельцев endpoint. На старте нужен peer
   с полной историей с высоты 1. Snapshot/state-sync доверенные параметры появятся
   только после фактического создания snapshot. Адреса заранее не придумывать.
6. Выбрать время UTC. Зафиксировать точные байты genesis и SHA256, выпустить
   отдельный public-genesis manifest с network ID, allocation, release SHA и подписью.
   Все операторы подтверждают один hash и корректный signing-state до старта.

Аттестация GitHub для software-only пакета уже есть, но она **не подписывает
будущий публичный genesis**. Способ доверенной публикации genesis manifest и
канал подтверждения его хеша нужно утвердить отдельно. Одноразовый CI GPG signer
не становится публичным издателем автоматически. Никакие службы не запускаются
на основании этого черновика.
