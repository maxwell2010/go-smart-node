# Проект публичного запуска MintCandy

Предложение для согласования с организаторами и четырьмя операторами.
Суммы, параметры и состав утверждаются до сборки итогового genesis.

## Идентификаторы сети

| Параметр | Предложение |
| --- | --- |
| Cosmos и CometBFT chain ID | `mintcandy_9905401-1` |
| EVM chain ID | `9905401` (`0x9724f9`) |
| Начальная высота | `1` |
| Время genesis | Согласовать с четырьмя операторами, указать в UTC |

Число `9905401` соответствует проверке идентификаторов в `mcnd`. В открытом
реестре EVM не найдено совпадения при проверке проекта 12 ноября 2026 года.
Повторите проверку перед утверждением и оформите регистрацию сети, когда будут
известны её публичные параметры. [Реестр EVM](https://github.com/ethereum-lists/chains)

## Начальное распределение DEL

Предлагаемый начальный объём - **100 000 DEL**. Один DEL равен `10^18 del`.

| Назначение | DEL | Куда зачислить |
| --- | ---: | --- |
| Стартовые стейки | 40 000 | Банковский баланс WDEL. Четыре обычные позиции по 10 000 DEL, по одной на оператора и его подтверждённого владельца. |
| Получатели из сообщества | 45 000 | Напрямую в утверждённые кошельки участников. |
| Казна разработки и эксплуатации | 14 000 | Отдельный утверждённый адрес. Предлагаемый порог расходования - три подписи из пяти после проверки кошелька. |
| Комиссии операторов | 400 | Четыре расходных кошелька по 100 DEL. |
| Комиссии IBC-relayer | 200 | Два расходных кошелька по 100 DEL. |
| Резерв DRC20 | 300 | Банковский баланс одного утверждённого контракта DRC20. |
| Резерв исходного ERC1155 | 100 | Банковский баланс утверждённого контракта, 100 единиц NFT с обеспечением 1 DEL на единицу. |
| **Итого** | **100 000** | **`100000000000000000000000 del`** |

Предлагается равное распределение 45 000 DEL по утверждённому списку
участников. После согласования критериев участия, списка и подтверждённых
адресов отсортируйте адреса без повторов. Разделите пул в `del` на число
получателей с округлением вниз. Первые адреса по этому порядку получают
дополнительно по одной минимальной единице до исчерпания остатка.
Казна стартует без стейка. Расходы на подготовку контрактов учитываются в
утверждённом бюджете, все фактические остатки в genesis входят в те же 100 000 DEL.

Учтите стартовые делегации один раз, в составе банковского баланса WDEL.
Резерв ERC1155 в этой схеме хранится непосредственно в DEL, отдельно от
резерва DRC20. `fee_collector` и `PositionVault` стартуют с нулевым балансом DEL.
Награды выплачиваются из собранных комиссий DEL, без новой эмиссии. Предлагаемая
начальная комиссия каждого валидатора - 5% от его доли наград. Сеть начинает с
собственного реестра балансов. [Суммы в минимальных единицах](public-launch-allocation.draft.json)

## Начальный состав и параметры

Четыре позиции по 10 000 DEL дают **10 000 единиц голосующей мощности** на
оператора, всего 40 000. Для выпуска блоков нужны подписи более двух третей
мощности, любые трое из четырёх дают 75%. В проекте заложен верхний предел
16 активных валидаторов для дальнейшего расширения состава. Имена, ключи,
стейк и адрес наград каждой из четырёх команд подтверждаются отдельно.
[Анкета операторов](VALIDATOR_LAUNCH_INTAKE.md)

Предлагаемые параметры профиля - базовый срок вывода DEL 28 дней, пороги
давности доказательств CometBFT 100 000 блоков и 48 часов, штраф за двойную
подпись 5%. При выплате учитываются оба порога давности и незавершённые штрафы.
Для простоя предлагается окно 1000 блоков, порог 50% подписей, штраф 1% и jail
на час. Таймер Gateway и срок вывода нативного DEL должны совпадать. Параметры
простоя и пороги давности нужно подтвердить для ожидаемого времени блока на
репетиции.

Текущий автоматический штраф ограничивает число учитываемых активных и
замороженных позиций двумя на валидатора суммарно. Каждый стартовый стейк
занимает одну такую позицию. Для массового делегирования потребуется отдельно
проверить расширение лимита при действующем ограничении газа.
[Текущий профиль консенсуса](NATIVE_CONSENSUS_REHEARSAL.md)

## Как довести черновик до итогового genesis

[Черновик genesis](public-genesis.draft.json) содержит известные поля в
формате приложения и четыре незаполненные записи операторов и стейков.
`null` отмечает данные, которые предстоит получить или сгенерировать. Для
итоговой сборки используйте полный свежий набор модулей из выбранного бинарника
`mcnd`. Для запуска нужен итоговый genesis после проверок ниже.

1. Получить согласованный реестр получателей, публичные данные операторов,
   адреса казны и владельцев обоих резервных активов. Утвердить параметры
   кривой и выпуск DRC20, идентификатор ERC1155 и владельцев его 100 единиц.
2. Подготовить состояние контрактов для согласованного профиля. Нужны байткод,
   хранилище, адреса и роли Registry, Gateway и библиотеки, NFTCenter,
   PositionVault, MasterValidator, WDEL, TokenCenter и CurveConverter,
   а также согласованные контракты DRC20 и исходного ERC1155. Проверить пустой
   vault квитанций с первым ID `1`. Сформировать четыре `evm_stake_bindings`
   из фактического состояния Gateway и сопоставить с нативными делегациями.
3. Собрать банковские балансы, `bank.supply` и `coin.params.base_volume`.
   Сверить их с суммой из проекта и с фактическим обеспечением контрактов.
   Начальный состав выводится из нативных стейков при `InitChain`.
   Верхний список валидаторов CometBFT и записи SDK staking и `gentx` пусты.
4. Проверить итоговый файл через `mcnd genesis validate` и холодный `InitChain`
   в изоляции. Проверить фактический состав, голосующую мощность и обеспечение.
   Для проверки выпуска блоков четырьмя процессами использовать отдельный
   тестовый genesis с одноразовыми ключами. При старте публичной сети каждый
   оператор подписывает своим ключом на своём оборудовании.
5. Собрать два публичных P2P-адреса от независимых операторов и адреса Comet RPC,
   EVM JSON-RPC и Cosmos REST. На старте нужен хотя бы один пир с историей с
   высоты 1. Параметры state sync появятся после создания проверенного snapshot.
   Согласовать время, подписать манифест с SHA256 genesis и Linux-архива и
   получить подтверждение всех четырёх операторов.
   [Порядок публикации и проверки](OPERATOR_LAUNCH.md#подписанный-пакет-и-проверка-оператором)

## Результат репетиции с четырьмя валидаторами

В GitHub CI использован отдельный тестовый chain ID `mintcandy_990012-1`
с EVM chain ID `990012`. Холодный `InitChain` принял четыре позиции по
10 000 DEL, проверил все 11 банковских строк и общий выпуск 100 000 DEL.
Пул сообщества представлен одним тестовым счётом. Для казны сверили публичный
ключ счёта с порогом 3 из 5. Для проверки расходования казны нужен отдельный
сценарий. [Прогон GitHub CI](https://github.com/maxwell2010/go-smart-node/actions/runs/43226218714)

Все четыре валидатора подписывали блоки. После остановки `d` на высоте 12
оставшиеся трое подтвердили блоки 14-16 с мощностью 30 000 из 40 000.
`d` сохранил свои 10 000 в составе на проверенных высотах. Наблюдающая нода
подключилась после блока 17, получила историю с блока 1 и подтвердила общий
AppHash на высоте 21. EVM JSON-RPC и Cosmos REST вернули 45 000 DEL для
тестового счёта на обеих проверенных высотах. Все процессы и адреса находились
в изолированном сетевом пространстве runner.
[Genesis, распределение и сетевой отчёт](https://github.com/maxwell2010/go-smart-node/actions/runs/43226218714/artifacts/13948965875)
