# Самоуправление валидатора

Команды предназначены для отдельной сети MintCandy. Они не управляют systemd, не меняют работающие ноды и не отправляют транзакции автоматически. Параметры своей сети и адрес MasterValidator берите из проверенного genesis и подписанного манифеста релиза.

## Просмотр

```bash
mcnd validator-control status 0xYOUR_OPERATOR --node tcp://127.0.0.1:26657
```

Ответ содержит высоту, запись валидатора и `avatar_uri`. Это чтение состояния через выбранный RPC. Для независимой проверки используйте доверенную локальную ноду. Приватный consensus key и ключ оператора - разные ключи; команды подписывают только ключом оператора в SDK keyring.

## Подготовка и подпись

Укажите точные Cosmos chain ID, EVM chain ID, свой адрес оператора, адрес MasterValidator, текущий nonce и цену газа в минимальных единицах MSP. Значения ниже - шаблон, а не готовые параметры публичной сети.

```bash
mcnd validator-control prepare \
  --chain-id mintcandy_9905401-1 --evm-chain-id 9905401 \
  --operator 0xYOUR_OPERATOR --master 0xAPPROVED_MASTER \
  --action disable --nonce 0 --gas 24000000 --gas-price 1000000000000 \
  --output-file disable-intent.json

mcnd validator-control sign --intent-file disable-intent.json \
  --from operator --keyring-backend file --home "$HOME/.mcnd" \
  --output-file disable-signed.json
```

`enable` включает участие, `disable` выключает. Подписанный запрос привязан к EVM chain ID, адресу MasterValidator, nonce, calldata, лимиту и цене газа. Повторное применение уже исполненного запроса отклоняется по nonce. Новый файл создаётся с правами `0600`; существующие файлы не перезаписываются. Пароли и приватные ключи не передаются аргументами и не печатаются.

Начальный лимит `24000000` включает проверку закреплённого профиля контрактов и нативного учёта. Это существующий предел сети, он не увеличивается. При указанной цене газа баланс должен покрывать предварительный бюджет до 24 MSP. Итоговая комиссия учитывает исполнение EVM и нативных проверок, а также минимальный оплачиваемый газ `MinGasMultiplier`: при значении `0.5` оплачивается не менее половины подписанного лимита. Поэтому весь неиспользованный лимит не обязательно возвращается. Уменьшайте лимит только по результатам оценки газа на той же версии ноды и контрактах.

Результат подписи содержит `raw_ethereum_tx`, хеш транзакции, `cosmos_tx_base64` и объект `cosmos_tx_json`. Проверьте запрос перед отдельной явной отправкой через доверенный RPC. Инструмент не отправляет его самостоятельно. При использовании внешнего подписанта вместо `--from` передайте `--signature-file` с 65-байтной Ethereum-подписью дайджеста из intent; адрес восстановленного подписанта обязан совпадать с оператором.

Только после проверки полей и решения отправить транзакцию:

```bash
# jq должен быть установлен. noclobber запрещает перезапись готового tx.json.
(set -C; umask 077; jq -e '.cosmos_tx_json' disable-signed.json > disable-tx.json)
mcnd tx broadcast disable-tx.json --chain-id mintcandy_9905401-1 \
  --node tcp://127.0.0.1:26657 --broadcast-mode sync
```

Успех синхронной отправки означает приём в mempool. Подтвердите включение в блок и результат исполнения, затем снова вызовите `validator-control status`. При ошибке исполнения проверьте актуальный nonce перед новой подготовкой запроса.

## Имя, описание, аватарка и комиссия

Создайте локальный `metadata.json`:

```json
{
  "name": "Мой валидатор",
  "description": "Описание оператора",
  "avatar_uri": "ipfs://YOUR_VERIFIED_CID/avatar.png",
  "commission": "0.05"
}
```

Подготовьте запрос как выше, заменив действие на `--action metadata --metadata-file metadata.json`. Укажите хотя бы одно изменяемое поле. В версии 1.1.1 поле `commission` принимает долю от `0.05` до `1`, то есть от 5% до 100%. Новая ставка применяется к следующим начислениям. Для уже начисленных сумм сохраняется ставка на момент начисления.

Имя ограничено 70 байтами, описание 280 байтами, URI 512 байтами, весь JSON 2048 байтами. Неизвестные, повторяющиеся и `null`-поля отклоняются. Для аватарки допустимы HTTPS и IPFS без пароля в URI; пустая строка очищает ссылку. Нода сохраняет ссылку, не скачивает и не отображает внешний контент. Проверку файлов, закрепление, безопасное отображение и резервное копирование выполняет отдельный слой хранения: [MEDIA_STORAGE.md](MEDIA_STORAGE.md).

## Границы полномочий

Оператор изменяет только собственного валидатора. Администратор MasterValidator не получает обхода этого ограничения в нативном учёте. Нельзя заменить consensus key или адрес получения наград через metadata, снять постоянное исключение ключа или обойти незавершённую обработку штрафа. Для jailed-валидатора обычное включение не заменяет проверенную процедуру unjail.

Изменение Online проходит через существующее расписание набора валидаторов с задержкой H+2. Состояние EVM, нативная запись и событие подтверждаются вместе; ошибка нативной проверки откатывает изменения вызова, но комиссия неуспешной транзакции оплачивается по обычным правилам EVM.

После `disable` дождитесь подтверждённого исключения ключа из эффективного набора валидаторов, прежде чем останавливать службу. До этого момента подписи ещё нужны по правилам текущего набора. `enable` возвращает участие по расписанию и не является командой запуска systemd.

Аватарка сохраняется в базе и переносится в genesis модуля валидаторов через поле `validator_avatars`. Команды `validator-control export-avatars` и `import-avatars` позволяют отдельно переносить ссылки в подготовленный genesis. [Порядок переноса, проверки и границы финансового экспорта](VALIDATOR_AVATAR_GENESIS.md).

## Проверки CI

```bash
cd network
go test ./app ./cmd/mcnd ./decimal/validator/settlement ./decimal/validator/keeper
go test -tags appstate ./systemcontracts -run '^TestOwnedAppNativeValidatorSelfControls$' -count=1 -v
```

Изолированный тест проверяет двух операторов, отсутствие чужих полномочий, ручное выключение и включение, изменение metadata/комиссии, откат недопустимой аватарки, повтор подписанной транзакции и сохранение данных после открытия базы заново. Проверки не используют реальные средства и работающие сети.

[Linux CI 44506992670](https://github.com/maxwell2010/go-smart-node/actions/runs/44506992670) успешно проверил все три стадии `seed/run/restart`. При лимите 24 млн и `MinGasMultiplier=0.5` каждый успешный `pauseSelf`, `updateValidatorMeta` и `unpauseSelf` записал `GasUsed=12000000`. При цене `1000000000000` минимальных единиц за газ это 12 MSP за вызов в данном стенде. Показатель включает минимальную оплату и задаёт верхнюю границу расхода исполнения; он не доказывает, что сами инструкции EVM и нативные проверки требуют ровно 12 млн газа. Оптимизация безопасного лимита остаётся отдельной задачей.
