# Изолированное обеспечение NFT-позиций

Решение для отдельной новой сети от 3 ноября 2026 года: штраф уменьшает
обеспечение только соответствующей позиции. Изменение контрактов и модели
совместимости ERC1155 одобрено. Этот документ фиксирует целевую модель;
её финансовая активация и сквозные проверки ещё не завершены.
[Подробный проект API и инвариантов](NFT_ISOLATED_POSITIONS.md).

## Причина изменения

Подписанный тест исходной модели использует один ERC1155 tokenId,
два NFT по одному у владельцев A/B и общий резерв 20 DEL. Владельцы
делегируют разным валидаторам; штраф 10% назначается только валидатору A.
В зависимости от порядка реализации штрафа и выхода получаются выплаты
9/10 либо 9,5/9,5 DEL. При заранее применённом штрафе обе последовательности
дают 9,5/9,5. Сжигается 1 DEL, но общая обеспеченность ERC1155 распределяет
потерю между владельцами. Сохранённые суммы отдельных стейков 9/10
не совпадают с фактическим требованием 9,5 каждой единицы общего пула.
[Полный исходный контроль](../../systemcontracts/owned/SHARED_1155.ru.md).

В выбранной модели ожидаются A=9 DEL и B=10 DEL при любом порядке выхода.

## Позиция и исходный NFT

- При изоляции исходные ERC1155 units погашаются, а их обеспечение
  извлекается из общего исходного пула в отдельное обеспечение позиции.
  Создаётся ERC721 receipt с уникальным полным uint256 идентификатором.
- Receipt хранит происхождение: сеть, исходные contract/tokenId, количество
  исходных units и связь с потреблёнными нативными subIDs. Эти сведения
  не подменяются идентификатором receipt.
- Фактическое custody определяется отдельными contract/receiptId/nativeID
  и живым subID receipt. Количество исходных units N и receipt units 1
  учитываются раздельно.
- После выхода возвращается изолированный receipt либо явно погашается
  его обеспечение. Автоматического возврата уменьшенного обеспечения
  в исходный общий fungible tokenId нет: это снова распределило бы штраф
  на остальных владельцев.
- Финансовый резерв принадлежит контракту обеспечения/NFT keeper.
  Validator keeper хранит права и ссылки, а не второй банковский баланс.

## Округление и разделение

Для исходного ещё fungible ERC1155 сохраняется равномерное целочисленное
обеспечение units: начальный резерв кратен количеству, последующий mint
вносит текущий резерв одной единицы, умноженный на количество новых units.
Пополнение исходного пула также распределяется равномерно. Kind и валюта
обеспечения не меняются неявно. Прямое внешнее зачисление на адрес контракта
не становится автоматически объявленным обеспечением конкретной позиции.

При разделении изолированной позиции с резервом R и исходным количеством N
дочерняя позиция для q units получает `floor(R*q/N)`, родитель сохраняет
остаток. Для q=N передаётся весь оставшийся R. После разделения обе позиции
имеют независимое обеспечение. Сумма резервов сохраняется, остаток не теряется.

Нулевой остаток после штрафа сохраняет вид backed-позиции; он не превращает
receipt в ReserveLess. Штраф сжигает фактическую потерю один раз. Перемещение
обеспечения при создании или разделении позиции само по себе не выпускает
и не сжигает нативный DEL. Комиссии учитываются отдельно.

## Обязательные проверки перед активацией

Обе последовательности выхода A/B, отложенная и явная реализация штрафов,
несколько штрафов с округлением, частичный выход/split, перевод позиции,
смена валидатора, принудительный выход, откат при ошибке события и OOG.
Для каждого случая сверяются backing, права владельцев, банковское предложение,
NFT supply, lineage и нативные индексы. Начальное распределение и общий
Native/EVM/IBC-процесс проверяются отдельно для конечной сборки.

До завершения этих проверок shared-pool ERC1155 не допускается в новый
финансовый профиль. Исторические исходники и mainnet replay не меняются.
