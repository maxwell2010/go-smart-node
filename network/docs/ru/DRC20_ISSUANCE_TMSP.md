# Выпуск DRC20 на изолированном стенде tMSP

Тестовый профиль использует chain ID `mintcandy_990098-1`, EVM chain ID `990098` и базовый denom `tmsp`. Одна tMSP содержит 10^18 атомов. Этот тариф действует в экспериментальной сборке. Для майнета адрес получателя 80% платы ещё предстоит утвердить.

| Длина тикера | Плата, tMSP | В тестовую казну | Сжигается |
|---|---:|---:|---:|
| 3 | 100 000 | 80 000 | 20 000 |
| 4 | 10 000 | 8 000 | 2 000 |
| 5 | 1 000 | 800 | 200 |
| 6-9 | 100 | 80 | 20 |
| 10 | 10 | 8 | 2 |

Оба семейства используют один реестр тикеров. Пользовательский интерфейс может показывать тикер заглавными буквами. Для вызова фабрики используется канонический тикер в нижнем регистре ASCII. Сохраняются ограничения фабрики на длину и алфавит, блокировки системных обозначений и отдельная проверка полного названия. При переносе исторического состояния проверяются монеты из genesis и зарегистрированные прокси обоих семейств. Два разных контракта с одним тикером требуют отдельного решения перед миграцией.

## Интерфейс для Консоли и SDK

Запросите `GET /mintcandy/issuance/v1/tariff` через Cosmos REST стенда. Ответ содержит `version`, `chain_id`, `denom`, `height`, `token_center`, `treasury`, `treasury_percent`, `burn_percent` и массив `tariffs` с восемью строками. Суммы в атомах передаются десятичными строками. Сверьте сеть, адрес фабрики и тестовой казны с доверенным профилем. Для этой версии тестовая казна имеет адрес `0x00000000000000000000000000000000Cafe9900`.

1. Выберите строку по длине канонического тикера. Обозначим `fee_atoms` через F, `backed_factory_component_atoms` через L, вклад в резерв через R. До подписи отдельно покажите F, R и ожидаемую сетевую комиссию.
2. Для резервного DRC20 закодируйте обычный вызов `createToken` и укажите EVM value = R + L. R должен удовлетворять минимуму фабрики. Нативный обработчик спишет дополнительно F - L, поскольку L уже уплачен при вызове фабрики. Общий расход равен R + F + газ.
3. Для безрезервного DRC20 закодируйте `createTokenReserveless` с EVM value = 0. Нативный обработчик спишет F. Общий расход равен F + газ.
4. Допишите 96 байт `approval_suffix` к ABI calldata до подписи EVM-транзакции. Суффикс состоит из Keccak-256 строки ASCII `MintCandy DRC20 issuance v1`, адреса казны и F. Адрес и сумма кодируются как два 32-байтных слова ABI. SDK должен проверить суффикс по этим данным. Поскольку кошелёк может показывать только EVM value, в Консоли необходимо явно показывать весь дополнительный дебет. При неподдерживаемой версии или недоступной котировке приостановите подготовку этой операции.
5. Успех проверяйте по квитанции и событию SDK `mintcandy_drc20_issuance`. В нём указаны `symbol`, `token`, `fee`, `treasury_amount` и `burn`. Сжигание уменьшает bank supply. При откате тариф, резерв, регистрация и развёртывание откатываются вместе. За включённую неуспешную транзакцию может взиматься газ.

## Проверка истории перед обновлением

По публичному EVM RPC майнета на блоке 30 838 (хеш `0xd85ea8c213c80d8513b9ac4aeb7a5c2152ddcb7827f9a3f876d57d0d115db507`) проверены события обеих фабричных операций с высоты 1. В genesis список пользовательских монет пуст. В событиях фабрики `0x4526d1f8cba2e043d904d425d1faaca9cef8b0fb` найдены два безрезервных токена. Вызовы `symbol()` на той же высоте вернули `test` и `cusdt`. Между ними коллизий нет. Проверка относится только к этому срезу. Перед будущей миграцией необходимо снова проверить историю до согласованной высоты и проверить нативное состояние на копии базы.
