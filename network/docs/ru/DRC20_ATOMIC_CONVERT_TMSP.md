# Обмен двух резервных DRC20 через tMSP

Тестовый профиль MintCandy использует chain ID `mintcandy_990098-1`, EVM ID `990098` и denom `tmsp`. Адрес TokenCenter берите из доверенного профиля этого развёртывания. Для обоих активов на одной высоте H запросите `GET /mintcandy/markets/v1/reserve?token=0x…&height=H`. Проверьте адрес токена, chain ID, denom, высоту, совпадение token_center с профилем и числовое поле atomic_convert_version, равное 1. Старые сборки поддерживают прямые покупки и продажи и не возвращают этот флаг.

## Вызов с кошелька

1. Выберите два разных зарегистрированных резервных токена и обычный адрес получателя. Все расчёты ведутся в целых атомах. На высоте H вызовите calculateSellOutput(amountIn) на входном DRC20, затем calculateBuyOutput(полученныеАтомыTMSP) на выходном. Промежуточный tMSP проходит через фабрику внутри транзакции.
2. Сверьте выпуск входного токена после сжигания с min_supply_atoms и остаток нативного резерва с min_reserve_atoms. Выход не должен превышать max_supply_atoms минус supply_atoms второго токена. Покажите ожидаемый выход, выбранный пользователем minOut и газ отдельно.
3. Для расходования входного токена кошелёк может вызвать approve(TokenCenter, amountIn), либо выдать такое же разрешение отдельным вызовом EIP-2612 permit на входном токене. Spender в обоих случаях равен адресу TokenCenter. Дождитесь успешной квитанции, затем проверьте allowance(owner, TokenCenter). Для обычной разовой сделки используйте точную сумму.
4. Отправьте на TokenCenter вызов `convert(address tokenIn,address tokenOut,uint256 amountIn,uint256 minOut,address recipient)` с EVM value = 0 с кошелька владельца. Для оценки газа укажите тот же from, to и calldata. Метод с девятью аргументами и встроенной подписью permit в этот интерфейс не включён.
5. При успехе swap использует ранее выданное разрешение и обновляет оба резерва и оба выпуска за одну транзакцию. При отказе состояние обоих токенов и allowance возвращается к значениям перед swap. Отдельный успешный approve сохраняет силу после отказа swap. Включённая в блок неуспешная транзакция может израсходовать газ.

## Квитанция

Проверяйте status квитанции. Успешный вызов даёт три события на входном DRC20 (Transfer от владельца к TokenCenter, Transfer при сжигании, ReserveUpdated) и два на выходном (Transfer при выпуске получателю и ReserveUpdated). Порядок нативной выплаты по продаже означает, что поле резерва первого ReserveUpdated отражает момент до отправки tMSP. Итог берите из состояния на высоте квитанции и события mintcandy_drc20_convert. Поля события для приложений: payer, recipient, token_in, token_out, input_atoms, native_atoms, output_atoms, min_output_atoms, in_volume, in_reserve, out_volume, out_reserve.
