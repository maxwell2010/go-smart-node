# Завершение возврата стейков

У запроса на возврат и выплаты разные состояния. Срок ожидания делает заявку доступной для завершения. Средства зачисляются только после исполнения `complete([id])` в EVM. Для проверки выплаты нужно сверять состояние заявки и результат исполнения. Удаление записи из нативной очереди или появление события в индексе само по себе выплату не подтверждает.

В Decimal на проверке 11 ноября 2026 года Explorer нашёл 2 663 просроченные заявки со статусом `Frozen`. Их состояние читалось напрямую из контракта. Console использует тот же идентификатор заявки для симуляции `complete([id])` и оценки комиссии перед подписью пользователя. В Testnet подписанный вызов зачислил средства, а повторный вызов контракт отклонил. История найденных событий показывает прекращение автоматических завершений до обновления на блоке 34 342 701. Причина остановки прежнего исполнителя по состоянию сети неизвестна.

В коде новой сети индекс хранит активные заявки на возврат по сроку и паре «Gateway, полный uint256 ID». Он создаётся вместе с привязкой к нативной записи и удаляется в той же операции при завершении. Для отбора используется время блока, включая точную секунду срока. Планировщик берёт до восьми заявок за вызов и сохраняет позицию обхода в базе. Позиция переживает обычный перезапуск. При экспорте и импорте индекс восстанавливается из активных привязок, обход начинается с начала очереди.

Для каждой заявки исполнение Gateway, обработка результата, снятие привязки и удаление одной совпавшей нативной записи должны происходить в общем кэше. Ошибка оставляет заявку в очереди, а обход переходит к следующим. Одинаковые по содержанию нативные записи учитываются по отдельности. На завершённую привязку повторная попытка не назначается. Принудительное разделегирование, переназначение стейка и возврат после заморозки относятся к разным очередям.

В обычном SDK-стейкинге ошибка завершения теперь откатывает изменения и возвращает запись в очередь. Нативная заявка с удержанием продолжает подчиняться правилам SDK для снятия удержания. В сборке для исторического воспроизведения Decimal исправление автоотзыва при превышении лимита валидатора действует только после высоты активации исправлений. При отказе постановки в EVM-очередь стейк сохраняется для следующей попытки.

При наличии профиля в состоянии сети приложение направляет подписанный `complete([id])` и автоматический возврат из EndBlock в один обработчик. Вызов сверяет байткод и роли Gateway, фактический результат EVM и нативную заявку. Для DEL подтверждается разворачивание WDEL. Для изолированной квитанции ERC721 меняется владелец соответствующего нативного NFT, а резерв и происхождение позиции сверяются с vault. Внутренние вызовы EVM без этого обработчика отклоняются. Автоматический проход делает до одной попытки за блок с лимитом 24 млн единиц газа SDK.

Обычный genesis запускается без этого профиля. Отдельный раздел `withdrawal_settlement` разрешает импорт ограниченного снимка с уже развёрнутыми контрактами и ожидающими возвратами. Во время `InitChain` нода сверяет весь массив замороженных заявок Gateway с нативной очередью, происхождением NFT, владением и фактическим обеспечением. Снимок также должен содержать записи `slashing.signing_infos` для валидаторов начального набора консенсуса. Ошибка останавливает запуск до принятия снимка. Успешно принятый профиль хранится в состоянии сети и загружается при перезапуске.

Импортированный Gateway принимает завершение имеющихся заявок. Для отдельного запуска с нуля флаг `withdrawal_settlement.enable_del_delegation` включает прямые подписанные `delegateDEL(validator)` и `withdraw(validator, WDEL, amount)`. Genesis требует заранее объявленных нативных операторов, активных в проверенном MasterValidator, пустых стейков и очередей в нативном снимке и нулевого остатка WDEL у Gateway. Оператор не получает консенсусный вес от этой настройки.

`delegateDEL` подтверждает выпуск обеспеченного WDEL и создаёт или пополняет одну нативную позицию для пары делегатор-валидатор. `withdraw` переносит запрошенную сумму в очередь с тем же ID заявки и сроком, что в EVM. Активный остаток и ожидающие возвраты учитываются отдельно. После срока `complete` сжигает WDEL и выплачивает сумму конкретной заявки. Hold, NFT, другие валюты и позиции со штрафами остаются закрыты для нового допуска. Обычный экспорт genesis активного финансового профиля остаётся выключен.

При эксплуатации следует сверять возраст старейшей заявки, число отложенных попыток и события `decimal_withdrawal_completed` в подтверждённых блоках. В событии указываются адрес Gateway и полный ID заявки в шестнадцатеричной записи.
