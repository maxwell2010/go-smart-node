# Финансовая валидация и оставшиеся ограничения

Состояние на 3 ноября 2026 года: development. Этот документ не подтверждает
готовность к production и не заменяет [общие условия выпуска](../../../docs/RELEASE_STATUS.md).

## Обычные финансовые проверки

- Для смешанного стейка 40 единиц прямого обеспечения и 60 единиц NFT
  проверяется единый штраф 10%. Исходный контракт в контрольном примере
  уменьшал итоговое требование до 84 вместо 90. Изолированное исправление
  даёт 36 + 54 = 90 при обоих порядках применения штрафов. Это ещё не
  доказательство корректности совокупного сжигания и всех способов вывода.
- Совокупное списание нужно сверять с суммой индивидуальных требований.
  Например, округление штрафа отдельно для двух позиций по 3 единицы может
  отличаться от округления для общего количества 6. Проверка этого случая
  и ограниченного по работе расчёта остаётся обязательной.
- Для новой сети выбрано настоящее сжигание: уменьшение нативного
  `bank supply` и соответствующего WDEL. Перевод на нулевой адрес или
  блокировка обеспечения не засчитываются как выполнение этого требования.
- Тесты должны отдельно учитывать комиссию транзакции, остаток обеспечения,
  требования владельцев, предложение WDEL и предложение нативного DEL.
  Ошибка сжигания или последующей операции должна откатывать всю связанную
  транзакцию; ожидаемая комиссия учитывается отдельно.
- Создание контрактов, mint, обычные переводы, pause/read/unpause,
  откат неуспешной операции и воспроизводимость артефактов проверяются
  на изолированных экземплярах приложения. Рабочие ноды не используются.

## Не выполненные дополнительные проверки

Дополнительные демонстрации обхода защит через специальные вложенные
контексты вызова не выполняются. Они не отмечаются как успешные и не
подменяются запуском в другой среде. Защитные проверки в реализации
сохраняются, но доказательство покрытия таких сценариев не заявляется.

Показанное сообщение об ограничении проверки не содержит имени команды
или теста. Поэтому нельзя достоверно приписать отказ конкретной операции.
Обычные финансовые результаты и не выполненные дополнительные проверки
учитываются отдельно.

## Условия завершения

До выпуска нужны совместная проверка финансовых модулей в конечной сборке,
полный цикл делегирования/штрафа/вывода с сохранением состояния после
перезапуска, учёт стоимости нативной обработки, проверка начального
распределения и обеспечения, а также повторные IBC и установочные проверки.
Неполная проверка безопасности не должна представляться аудитом.
