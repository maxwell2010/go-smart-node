# Покупка и продажа резервных DRC20 на стенде tMSP

Интерфейс рынка версии 1 предназначен для экспериментальной сети `mintcandy_990098-1`, EVM ID `990098`. Для SDK точка входа в сделку - адрес зарегистрированного резервного токена. Кошелёк подписывает обычную EIP-155 транзакцию этой сети. Получателем в этом профиле может быть обычный кошелёк. Нативный газ учитывается отдельно от входа и выхода сделки.

| Действие | Метод ABI DRC20 | Селектор | EVM value |
|---|---|---|---|
| Покупка | `buy(uint256 minTokensOut,address recipient)` | `0x7deb6025` | Вход в атомах tMSP |
| Продажа | `sell(uint256 tokensIn,uint256 minNativeOut,address recipient)` | `0xd04c6983` | 0 |
| Расчёт токенов за tMSP | `calculateBuyOutput(uint256 nativeIn)` | `0x6cc94a2b` | 0 |
| Расчёт tMSP за токены | `calculateSellOutput(uint256 tokensIn)` | `0xc193d62e` | 0 |

## Подготовка сделки

1. Получите `GET /mintcandy/markets/v1/reserve?token=0x…` у доверенного REST-узла. Версия 1 возвращает `chain_id`, `native_denom`, `height`, `token`, `symbol`, `crr`, `supply_atoms`, `reserve_atoms`, `min_supply_atoms`, `max_supply_atoms` и `min_reserve_atoms`. Суммы закодированы десятичными строками. Необязательный параметр `height` закрепляет снимок за доступной высотой.
2. На той же высоте вызовите метод расчёта через `eth_call`. Доступная эмиссия равна `max_supply_atoms - supply_atoms`. При продаже должны сохраниться и минимальный запас tMSP, и минимальный выпуск DRC20. Метод расчёта возвращает результат кривой, поэтому ограничения на исполнение проверяются дополнительно.
3. Покажите котировку и минимальный выход, рассчитайте газ через `eth_estimateGas` для конкретных `from`, `to`, `data` и `value`. Ставку проскальзывания выбирает пользователь. При включении в блок контракт заново считает результат по текущему резерву. Доступ к кривой без `approve` обусловлен тем, что при продаже токены сжигаются со счёта подписанта.
4. Проверьте `status` квитанции. На успехе DRC20 выдаёт `Transfer` (выпуск или сжигание) и `ReserveUpdated`. При продаже контракт испускает второе событие до перевода tMSP, поэтому его поле резерва отражает промежуточный баланс. Финальные значения берите из состояния на высоте квитанции. Нативная нода также публикует `mintcandy_drc20_trade` с полями `side`, `payer`, `recipient`, `token`, `native_atoms`, `token_atoms`, `volume` и `reserve`.

## Причины отказа

| Селектор Solidity | Причина |
|---|---|
| `0x763303a6` | `NewSupplyTooLarge()`, покупка превысила максимальный выпуск |
| `0xc9f16362` | `NewSupplyTooSmall()`, продажа опустила бы выпуск ниже минимума |
| `0x7da7f44d` | `NewReserveTooSmall()`, после продажи в резерве осталось бы слишком мало tMSP |
| `0x6594b822` | `InsufficientAmountOutput()`, выход меньше подписанного `minOut` |

Квитанция неуспешной сделки содержит `status=0`. Для диагностики Solidity доступны данные отката симуляции. У нативного обработчика свои текстовые причины, в том числе `MC_TRADE_UNREGISTERED`, `MC_TRADE_RECIPIENT`, `MC_TRADE_PAUSED`, `MC_TRADE_BUY_DELTA`, `MC_TRADE_SELL_DELTA` и `MC_TRADE_RECEIPT`. Числовой JSON-RPC код транспорта сам по себе не определяет причину. Оплата сетевого газа возможна и при отказе.

Полные ABI входят в [артефакт DRC20](../../systemcontracts/artifacts/DRC20.json). Для методов сделок приложение должно проверить доступность интерфейса, версию сети и идентичность контракта. Выпуск токена использует отдельный [тариф регистрации](DRC20_ISSUANCE_TMSP.md).
