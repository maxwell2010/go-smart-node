# Совместимость ASCII Armor в объявленной копии SDK 0.53.8

Это изменение зависимостей отдельной разрабатываемой сети. Оно не меняет
Decimal mainnet, финансовую модель, состояние сети или формат транзакций.
Полный интеграционный релиз остаётся development до остальных проверок.

## Причина и выбранный вариант

[GO-2026-5932](https://pkg.go.dev/vuln/GO-2026-5932) отмечает старый
`golang.org/x/crypto/openpgp` как неподдерживаемый. SDK 0.53.8 использует
[его ASCII Armor](https://github.com/cosmos/cosmos-sdk/blob/v0.53.8/crypto/armor.go)
для экспорта и импорта ключей. На момент проверки 3 ноября 2026 года
ветка SDK `release/v0.53.x` сохраняла этот импорт; готовый совместимый
патч SDK в этом исследовании не найден.

Используется полный объявленный исходный SDK 0.53.8 в
`third_party/cosmos-sdk`, с заменой в Go module graph и меткой
`v0.53.8-mintcandy.1` в `UPSTREAM.json`. Каноническая версия семейства
остаётся 0.53.8. Это не новый SDK major, не модульный alias и не исключение
из результатов сканера. Альтернатива с build overlay отклонена: её пришлось бы
согласованно применять к сборке, тестам, установщику и сканерам.

Каноническая копия содержит 2138 файлов, около 40352 KiB на диске Linux.
Полный список и SHA-256 каждого исходного файла закреплены в `UPSTREAM.json`,
вместе с исходным commit, module h1, go.mod h1 и SHA-256 Go module ZIP.
Сохранены исходные лицензии и notices. Новые файлы добавлены в исходники
проекта; кэш Go и другие рабочие копии не изменяются.

## Точный объём изменений

В канонической копии изменены только:

- `crypto/armor.go`: поддерживаемый импорт ProtonMail и вызов адаптера Decode;
- `go.mod`: явная зависимость `github.com/ProtonMail/go-crypto v1.5.2`;
- `go.sum`: две контрольные суммы этой зависимости.

Добавлены `crypto/internal/armorcompat/armor.go`, его обычные тесты и
BSD-лицензия сохранённого CRC-24 checksum routine. Контрольная сумма
не является криптографической аутентификацией. Шифрование, Argon2,
ChaCha20-Poly1305, прежний bcrypt/xsalsa20, алгоритмы ключей и подписей
не изменены.

ProtonMail уже присутствовал в MVS как v1.1.5. Здесь выбирается v1.5.2 и
его ASCII Armor реально входит в зависимости `mcnd`. Другие выбранные
версии модулей не меняются; Circl 1.6.3 уже присутствовал. Корневой
`go.mod` явно сохраняет SDK replacement и необходимую зависимость.

## Зачем нужен адаптер CRC

[Поддерживаемый декодер](https://github.com/ProtonMail/go-crypto/blob/v1.5.2/openpgp/armor/armor.go)
больше не проверяет CRC. Простая замена импорта поэтому ослабила бы
прежнее обнаружение повреждённого файла ключа.

Проверка с каноническим SDK подтвердила: отсутствие CRC допускается,
неверная CRC отклоняется, после CRC требуется завершающая строка блока.
Адаптер сохраняет эти правила. Заголовки и base64 декодирует поддерживаемая
библиотека. Вход передаётся ей по одной строке: это позволяет отдельно
проверять именно тело выбранного блока, не захватывая следующий блок.
Сохраняется прежнее ограничение длины строки тела и отклонение лишних
пробелов в ней. Возвращаемые ошибки относятся к поддерживаемому пакету;
тождество старых Go concrete error types не обещается.

## Проверка и ограничения

Обычные тесты сравнивают канонические Info, публичный и зашифрованный
синтетический приватный ключ, неверный пароль, текущую и прежнюю KDF,
CRLF, необязательную CRC, неверную CRC, преамбулу и следующий блок.
Все ключи искусственные и не используются в сети.

Воспроизводимые команды из `network`:

```sh
go mod download
go mod verify
python3 scripts/verify_owned_sdk.py --compiled
go test -mod=readonly -p 1 ./securitytests -run TestCanonicalSDKArmorFixtures
go test -mod=readonly -p 1 github.com/cosmos/cosmos-sdk/crypto/internal/armorcompat github.com/cosmos/cosmos-sdk/crypto github.com/cosmos/cosmos-sdk/crypto/keyring github.com/cosmos/cosmos-sdk/crypto/keys/secp256k1 github.com/cosmos/cosmos-sdk/crypto/keys/ed25519
CGO_ENABLED=0 go test -mod=readonly -p 1 github.com/cosmos/cosmos-sdk/crypto/keys/secp256k1 github.com/cosmos/cosmos-sdk/crypto/keys/ed25519
go test -mod=readonly -p 1 ./app ./cmd/mcnd
```

Проверяющий скрипт закрепляет канонический inventory и точные отличия,
отклоняет замену ProtonMail на alias/local source и проверяет отсутствие
старого OpenPGP в фактических default imports `mcnd`. Он не исправляет
`go.mod`/`go.sum`. Установщик и Linux CI вызывают эту проверку, packager
проверяет SDK source и включает Apache/BSD notices вместе с manifest.

Локальная замена SDK ограничивает автоматическое сопоставление его версии
с базой уязвимостей. Отсутствие GO-2026-5932 после смены imports само по себе
не доказывает безопасность. Нужны новые полные source/binary captures,
привязанные к собранному commit, и отдельная проверка advisories для
канонического SDK 0.53.8. Официальный OSV-запрос этой версии по-прежнему
возвращает GO-2023-1821 и GO-2023-1881 для `x/crisis`; этот пакет отсутствует
в default imports `mcnd`. Это ограниченная классификация package reachability,
а не закрытие всей поверхности SDK. Старые captures других commit остаются
историческими и не переименовываются в результаты новой сборки.
